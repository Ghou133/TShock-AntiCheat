> 默认 `ObserveOnly` 不产生新的作弊账号永封，但仍可能执行独立的输入安全、资源限制和维护模式控制，**不等于完全无副作用的旁路**。请勿直接用于唯一的正式世界。

## 项目解决什么问题

本项目在现有 TShock 服务器内工作，不重写游戏服务器，也不要求玩家安装配套客户端。重点是检查服务端可验证的异常请求、限制明显的资源滥用，并在身份与规则证据完整时执行可恢复的账号处罚。

当前开发重点是异常 NPC 伤害与批量击杀、异常掉落物清除、公共世界改动、有限的生命同步、召唤数量和物品规则。目标是**可靠识别与处置**，而不是承诺首次破坏前零损失或覆盖全部作弊行为。

### 三类结果，分别处理

| 结果 | 含义 | 处置原则 |
| --- | --- | --- |
| 不确定 | 缺少上下文、来源或合法例外未排除 | 保留有限观测，不把重复怀疑累加成永封 |
| 输入不安全 / 资源超额 | 越界、畸形输入或超过有界工作预算 | 可独立拒绝请求；不等于证明账号作弊 |
| 已证明的违规 | 当前规则、运行环境、账号归因和必要前提全部满足 | 只有获准的规则才能进入持久处罚链 |

## 开发路线

| 阶段 | 交付目标 | 进入下一阶段的条件 |
| --- | --- | --- |
| **R0 · 公开工程基线** | 文档入口、公共测试、环境说明、已知问题登记 | 干净克隆能运行公开检查，失败可解释且不被隐藏 |
| **R1 · 运行包可复现** | 发布可再现的依赖来源、补丁流程及版本清单 | 第三方能构建并验证同一运行包；升级后重新验证规则 |
| **R2 · 模块化整理** | 按功能域分目录、收薄插件入口、隔离退役代码 | 每次迁移保留行为，Hook 注册/释放与现有回归通过 |
| **R3 · 重点能力闭环** | 逐项完成伤害、掉落物、世界资源、生命及召唤场景 | 正向场景与原版反例、真实身份归因和处置结果一致 |
| **R4 · 发布与维护** | 运维状态、恢复流程、版本化发行及长期回归 | 候选 DLL 有对应源码和证据，完成真实客户端与重启测试 |

阶段代表依赖顺序，不是完成率或发布日期。R1/R2 的独立任务可以并行，R3 的测试也可以提前准备；生产发布不能跳过运行包复现与误判验证。每项任务的编号、代码范围、前置条件与验收标准见 [路线图](docs/ROADMAP.md)。

## 技术架构

```text
客户端请求 / 原生事件
          │
          ▼
TShock 适配层：解析、真实会话、服务器上下文、Hook 生命周期
          │
          ▼
规则层：纯判定、有限窗口、资源预算、必要前提
          │
          ▼
核心层：资格检查、账号隔离、不可变处罚意图
          │
          ├── 观察日志：有限记录，不参与自动定罪
          └── 处罚日志 → 主线程调度 → TShock 账号封禁存储
```

| 技术 | 用途 |
| --- | --- |
| C# / .NET 9 | 核心、规则与服务器适配；构建 SDK 由 `global.json` 约束 |
| TShock / TSAPI / OTAPI | 游戏服务器接入及原生事件上下文，需要匹配的外部运行包 |
| MonoMod.RuntimeDetour | 有限原生方法挂钩；版本和线程假设必须核验 |
| System.Text.Json / 本地文件日志 | 有界观测、处罚意图及运行安全标记 |
| NUnit / GitHub Actions | 公开单元回归；不替代原生运行包与游戏客户端验收 |

核心与适配层职责、现存耦合和目标目录见 [架构说明](docs/ARCHITECTURE.md)。

## 构建与验证

### 先运行不依赖游戏运行包的测试

安装 .NET 9 SDK（`global.json` 要求至少 9.0.300，允许同一主次版本内更新的功能带），在仓库根目录执行：

```powershell
dotnet --version
dotnet restore AntiCheat.Public.slnf --locked-mode
dotnet test AntiCheat.Public.slnf -c Release --no-restore
python tools/repository-checks/check_repository.py
```

公开测试覆盖 Core、Rules、Persistence、Progression 和 RuleExtraction。部分平台专属用例会明确跳过；**测试通过不表示 Linux 游戏服受支持，也不表示插件已取得生产资格**。

### 构建服务器插件

```powershell
dotnet build src/AntiCheat.Plugin.TShock/AntiCheat.Plugin.TShock.csproj `
  -c Release -p:TShockBaselineRoot="C:\path\to\audited-server"
```

**不要把“对应 Terraria 1.4.5.8”理解为任意 TShock 运行包都能加载。** 当前接入校验要求 Windows x64、CLR `9.0.7`，以及源码锁定的 TShock/TSAPI/OTAPI 程序集；部分接线依赖仓库外的定制补丁。公开依赖复现流程尚未齐备，这是 R1 的发布阻塞项，不应通过删除校验来绕过。

依赖布局、实际产物、数据放置及原生测试前提见 [构建指南](docs/BUILDING.md)。

## 配置与运维

配置位置是 TShock 保存目录内的 `anticheat.json`。一个保守的观察配置如下：

```json
{
  "ExecutionScope": "ObserveOnly",
  "M18CandidateMode": "Auto",
  "M18RecordObservations": true,
  "M18EnableBlocks": false,
  "M18EnableServiceKick": false,
  "M18EnablePermanentSanctions": false,
  "ExperimentalLiquidScheduler": false
}
```

这些 `M18` 开关只控制对应候选模块，不是全插件安全控制的总开关。配置字段、默认值、隔离要求和实际日志位置见 [配置说明](docs/CONFIGURATION.md)。

## 已知限制

**发布条件尚未闭合。** 当前运行包严格锁定，外部补丁复现不完整；源码中的部分生产规则登记仍指向未公开的历史审计文件。不能用漂亮的文档或公开 CI 通过替代这些证据。

**重点检测仍有缺口。** 普通批量击杀和异常掉落物清除还没有可发布的账号处罚闭环；生命、召唤与物品规则只覆盖有限场景。默认观察不等于已经阻止破坏。

**结构清理尚在进行。** 历史阶段前缀、实验工具和部分退役模块仍在源码中；REST 接线与退出范围的声明尚需统一。完整清单及优先级见 [审查记录](docs/REVIEW-2026-09.md)。
